# Safire support

Safire is under active development. The current 1.5.x release line and current `main` branch receive best-effort community support through GitHub Issues; older releases and source snapshots may not receive fixes.

## Before opening an issue

1. Read [README.md](README.md) and the [documentation index](docs/README.md).
2. Search existing issues for the same symptom.
3. Reproduce the problem with the current `main` branch when practical.
4. Create a temporary vault containing only invented notes.
5. Remove usernames, local paths, note text, tokens, and other identifying data from screenshots and logs.

## Bug reports

Use the repository’s bug-report form and include:

- Safire version or commit;
- operating system, architecture, version, and run mode;
- clear reproduction steps;
- expected and actual behavior; and
- sanitized diagnostics only when they are necessary.

Do not upload a real vault, private note, backup, environment file, credential, or installer from an unknown source.

## Feature requests

Use the feature-request form. Explain the workflow problem, the desired result, alternatives considered, and any effect on vault privacy or data handling.

## Security reports

Do not report vulnerabilities in a public support issue. Follow [SECURITY.md](SECURITY.md).

## Scope

Support can cover Safire source builds, documented Windows/macOS/Linux packaging, and reproducible application behavior. General Node.js or operating-system administration, third-party agent configuration, and recovery of unrelated files may require support from those projects or platforms.
